# 2026-11-26: "Bisync stuck" investigation and memory repo setup

## Asked
Running `./rclone-bisync-Gdrive.sh Gdrive` printed `Bisync already running for Gdrive, skipping` repeatedly from 16:16 to 16:31. `Gdrive-Work` synced fine at 16:16.

## Found
- **Not stuck.** A real run started at 16:15:20 (`rclone-bisync-Gdrive@Gdrive.service`, started by the watcher through `sudo rclone-trigger-bisync Gdrive`).
- At 16:15:31 bisync detected `Path2: 1432 changes: 716 new, 0 modified, 716 deleted`. That was a **local rename of a ~716-file folder**. Bisync uploaded all 716 under the new name and deleted the 716 old ones on Drive (~116 MiB). This lasted until ~16:30.
- The journal showed nothing from 16:15 to 16:30 because the script buffers output in `$OUTPUT` (ISSUES #3). The whole run's log landed at 16:30:01–03, including a flood of `--progress` lines.
- At ~16:30:13 the post-check found differences and the retry loop started a **second** bisync pass (PID 149509), so the "already running" messages continued. Its outcome wasn't checked in this session.
- The watcher's `sudo rclone-trigger-bisync` call stayed blocked the whole time (15+ min, ISSUES #2).
- Earlier advice in this chat to "switch to flock" was **out of date**: the live script has used `flock` + `--max-lock 30m` since 2026-10-04. It was spotted only after capturing the real files, which is the motivation for this repo.

## Changed
- Created the memory structure in this repo. Captured `rclone-bisync-Gdrive.sh` and `rclone-watch-Gdrive.sh` from `~/.script/` (device bridge access to `~/.script` granted).
- Nothing changed on the laptop.

- **Lost log lines:** Pass 1's ending, the `Changes detected… rerunning` line and pass 2's `Starting bisync.` are missing. When pass 1 ended, the script dumped tens of thousands of `--progress` lines at once. That very likely hit journald's default rate limit (10 000 messages / 30 s per unit), so lines were dropped. Confirm with `journalctl --since 16:29 --until 16:32 | grep -i suppressed`. As a result, the 16:22–16:30 tail of pass 1 can't be reconstructed. ISSUES #3 raised to H.
